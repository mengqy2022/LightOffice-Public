# 轻量定位与已有测量

## 0.8.0.0 本机实测

[脱敏原始测量JSON](../examples/performance-0.8.json)包含程序哈希、硬件、输入、采样定义与窗口重复开关结果。Windows 11 build26300、i9-12900H、约64GB内存，非低配机器。没有强制GC或裁剪工作集；同时存在系统和其他测试负载，耗时不是跨机基准。

| 场景 | 耗时 | 观测值 |
|---|---|---|
| 100 MiB CSV，102400条 | 全量另存8.20秒；取消126毫秒 | 独立数据处理进程采样私有字节峰值38.43 MiB，最大Dispatcher间隔53毫秒 |
| 500 MiB CSV，512000条 | 全量另存37.29秒；取消122毫秒 | 同进程采样私有字节峰值38.94 MiB，工作集峰值40.46 MiB，最大Dispatcher间隔50毫秒 |
| 30张2400×1600 PNG等比缩小 | 约1.99秒（包含处理后300毫秒等待） | 独立图片测试进程采样私有字节峰值159.55 MiB，最大Dispatcher间隔46毫秒 |
| 完整Main后台运行 | 5.015秒采样内CPU281.25毫秒 | 工作集88.86 MiB、私有字节101.41 MiB；含托盘与钩子，不同于上述独立数据处理进程 |
| 连续开关任务窗口 | 40/80/120次 | 句柄均934；私有字节约157.13/157.14/157.46 MiB，最后采样约157.46 MiB |

CSV行包含较长合成文本，不代表所有列数、编码或算法。峰值为Dispatcher定时采样，可能漏掉短峰；512/768 MiB仅为该专项的验收预算，不是软件强制内存上限。取消耗时不包含随后等待。120次短测不能证明长期无泄漏。没有结构化XLSX导入或500MB–2GB Excel承诺。

## 使用时的资源边界

数据预览最多 200 条；去重 / 分组状态各有预算，大量唯一键仍会占内存。图片按像素解码，高分辨率图片可能远大于磁盘文件体积；批处理逐张运行。重任务排队减少同时叠加，可选办公引擎运行时的内存也应计入总资源。

当前数据科学不导入 XLSX，不承诺 500 MB–2 GB Excel 快速处理。PDF、图片和压缩的支持边界见各专题；单一“最大文件大小”不能准确表达这些能力。

## 完整基准后续需要补什么

记录产品精确哈希、系统 / CPU / RAM / 磁盘、输入生成方法、编码、行列数及唯一键比例；分别测试冷 / 热启动、空闲、普通与高基数 CSV、高分辨率图片、PDF、外部引擎。每项重复多次，记录端到端用时、峰值工作集 / 私有字节和关闭后的残余资源，再与同机同场景旧版比较。长期常驻、休眠恢复和真实混合 DPI 也需独立验收。
