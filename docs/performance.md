轻舟基础包不捆绑浏览器、LibreOffice、Python / R 或大型模型。磁盘包体、应用常驻内存和可选引擎子进程分别统计；逐记录读取也不意味着整个进程恒定内存。

## 已有启动与空闲采样

下面是 2026-11-11 保存的历史本地开发构建采样，版本字段为 0.6.0.0。**它不是公开 Release 安装包或当前 0.7.2 的性能基准**。构建 SHA-256 和三次采样保存在[脱敏测量 JSON](../examples/performance-0.6.json)，移除了本地路径与进程标识。

| 项目 | 记录值 | 含义 |
|---|---|---|
| 首份状态 | 492 ms | 新进程、系统缓存已热；不是冷磁盘启动或首次窗口响应时间保证 |
| 约 20 秒工作集 | 77.75 MiB | 该次采样的驻留页，非峰值 / 内存上限 |
| 约 20 秒私有字节 | 92.00 MiB | 进程私有提交，含义不同于工作集 |
| 句柄 | 581 | 当时采样值，非长期稳定性结论 |

没有强制 GC 或裁剪工作集；不含外部办公 / 压缩引擎。历史记录未包含完整 CPU 型号、内存、Windows build 和磁盘条件，因此不据此作跨机器比较。后续完整基准需补全环境后重新测量。

## 当前可复现的小样例

| 场景 | 输入与输出 | 证明什么 |
|---|---|---|
| CSV | 6→5 条、日期转换、分组输出与 PNG | 这组数据的功能结果，不代表百万行速度 |
| PDF A4 | 三页、两页非 A4→全部 A4 | 页尺寸、文字与等比变换，不代表超大 PDF 资源峰值 |
| 图片批处理 | 1200×800 / 800×1200 / 320×240→600×400 / 400×600 / 原尺寸 | 等比缩小、不放大与输出，不代表任意批量吞吐 |
| 改名恢复 | 两个合成文本文件执行并恢复 | 该路径下的改名和哈希恢复，不代表全部文件系统兼容 |

这些输入与结果都在[示例目录](../examples/README.md)。本轮没有为它们公布耗时、吞吐或峰值内存，避免把文档制作进程的测量误当产品基准。

## 使用时的资源边界

数据预览最多 200 条；去重 / 分组状态各有预算，大量唯一键仍会占内存。图片按像素解码，高分辨率图片可能远大于磁盘文件体积；批处理逐张运行。重任务排队减少同时叠加，可选办公引擎运行时的内存也应计入总资源。

当前数据科学不导入 XLSX，不承诺 500 MB–2 GB Excel 快速处理。PDF、图片和压缩的支持边界见各专题；单一“最大文件大小”不能准确表达这些能力。

## 完整基准后续需要补什么

记录产品精确哈希、系统 / CPU / RAM / 磁盘、输入生成方法、编码、行列数及唯一键比例；分别测试冷 / 热启动、空闲、普通与高基数 CSV、高分辨率图片、PDF、外部引擎。每项重复多次，记录端到端用时、峰值工作集 / 私有字节和关闭后的残余资源，再与同机同场景旧版比较。长期常驻、休眠恢复和真实混合 DPI 也需独立验收。
